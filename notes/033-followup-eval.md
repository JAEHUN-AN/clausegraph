# 033 — 후속 질문 분류를 재고, 방금 만든 기능에서 버그를 찾았다

[notes/032](032-multi-turn.md)에서 후속 질문 분류를 규칙으로 만들고 이렇게
적어 뒀다.

> 분류는 규칙 기반이고 **평가셋이 없다.**

없는 채로 두면 "규칙이 잘 돈다"는 건 인상일 뿐이다. 그래서 만들었고,
**만들자마자 그 기능의 버그를 잡았다.**

## 먼저 — 이 평가의 정직성 문제

후속 질문 말뭉치는 없다. 금감원이 공개하는 것은 **분쟁 사례의 3인칭 요약**
이지, 판정을 듣고 난 사람이 되묻는 말이 아니다.

> 신청인은 2024.3월 어깨 질환으로 … 입원의료비를 청구하였으나, 보험회사가
> 통원 대상이라고 임의로 판단하여 … 부당하다며 입원보험금 지급을 요청

이걸 후속 질문이라고 우기면 평가가 아니라 분장이다. 그러니 질문은 내가
써야 하는데, **규칙도 내가 쓰고 문제도 내가 쓰면 그것도 평가가 아니다.**

둘로 나눠 재고 따로 보고한다.

| | 무엇 | 라벨 | 무엇을 재는가 |
|---|---|---|---|
| A | 내가 쓴 질문 25건 | 손 | 분류 체계를 덮는가 — **내 말투 편향 있음** |
| B | 실제 분쟁 문장 160건 | **기계** | 실제 말에 대고 헛짚지 않는가 |

### B에 속임수가 없는 이유

실제 분쟁 문장으로 **청구를 만들고**(`extract_claim`), **같은 문장을 후속
질문으로 되먹인다.** 그러면 그 문장의 모든 사실은 이미 청구가 아는 값이다.
따라서

> 이때 `NEW_FACTS`가 뜨면 **정의상 헛짚음이다.**

손 라벨이 필요 없다. 정답이 구성으로 정해진다.

재는 것은 *"이미 아는 값을 되물었는데 재심사로 보내는"* 실패다. 그게 잦으면
사용자는 무슨 말을 하든 "다시 심사했습니다"를 듣고, 후속 질문 기능이 있으나
마나가 된다. 실제 분쟁 문장에는 숫자가 빽빽하다 — 과실비율 60%, 부상등급
12급, 8주(56일), 8차 KCD. 내가 쓴 짧은 질문으로는 안 나오는 밀도다.

## 첫 결과: 100%였고, 그게 문제였다

```
A  분류 정확 24/25
B  헛짚음 0건   깨끗함 100.0%
```

B의 100%를 그대로 적을 뻔했다. **무엇의 100%인지 세어 보기 전까지는.**

| 축 | 160건 중 값이 잡힌 사례 |
|---|---:|
| 진단코드 | 77 |
| **금액** | **0** |
| 입원일수 | 0 |
| 일자 | 3 |

**금액 축이 한 번도 발화하지 않았다.** 값을 못 본 사례는 통과한 게 아니라
재지 못한 것이다. 거저 맞은 것들을 모아 놓고 100%라고 말할 뻔했다.

## 왜 금액이 0이었나 — 그리고 진짜 버그

`extract.py`의 금액 정규식이 이랬다.

```python
_AMOUNT_RE = re.compile(r"([\d,]{4,})\s*원")
```

**숫자 네 자리 이상 + 원.** 기계가 적은 금액만 읽는다. 사람은 그렇게 쓰지
않는다.

| 말 | 잡히나 |
|---|---|
| "3,000,000원" | ○ |
| "300만원" | **✗** |
| "300만 원" | **✗** |
| "3백만원" | **✗** |
| "1억원" | **✗** |

그리고 이게 notes/032가 막겠다고 만든 바로 그 실패로 이어진다.

```
"작년에 이미 300만 원 받았는데 왜 부지급이죠"   ->  WHY
```

**`WHY`다.** 새 사실을 못 봤으니 낡은 DENIED를 근거 조항까지 붙여 설명한다.
notes/032가 "이 층에서 가장 나쁜 실패"라고 적어 둔 것이 그대로 일어난다.

내 테스트는 전부 통과하고 있었다. 내가 `3,000,000원`으로 썼기 때문이다.
**기능을 만든 사람이 그 기능이 다루기 쉬운 입력으로 시험한 것**이고,
평가셋을 실제 문장에 대 보고서야 드러났다.

### 고친 것

금액 파서를 단위까지 읽도록 바꾸고(`parse_amounts`), `extract.py`와
`followup.py`가 같은 것을 쓰게 했다. 억·천만·백만·만을 푼다. 조문 번호나
횟수를 금액으로 읽지 않도록 1,000원 미만은 버린다.

한글 수사(`삼백만원`)는 여전히 못 읽는다. 적어 둔다.

이 수정은 `claimed_amount`에도 걸린다 — 지금까지 *"수리비 300만원을
청구합니다"* 같은 청구는 **금액을 0으로 읽고 있었다.** 후속 질문보다 그쪽이
더 큰 자리다.

## 두 번째 결과: 금액 축이 살아나자 헛짚음이 나왔다

```
B  헛짚음 6건   깨끗함 96.2%   (금액 축 0 -> 11건 발화)
```

여섯 건 모두 원인이 같았다.

> [57] 자동차 사고로 중고차량(**사고 직전 차량가액 300만원**)에 대해 수리가
> 가능하여 견적서 상 **수리비용 400만원**을 청구

`Claim`은 금액을 **하나만** 들고 있다(`claimed_amount`). 서술에 둘이 나오면
앞의 것만 담기고, 되먹였을 때 뒤의 것이 "새 값"으로 보인다.

고친 방식은 검출기를 무디게 하는 쪽이 아니었다. **청구가 만들어진 서술에
있던 금액 전부**를 아는 값으로 세게 했다 — 이미 한 번 말한 값은 새 사실이
아니다. 기지급액·자기부담 누적도 같이 넣었다.

## 최종

```
A  분류 정확 25/25   새 사실 놓침 0   헛짚어 재심사 0
B  헛짚음 0/160      값이 잡힌 사례 85/160 (진단코드 77, 금액 11, 일자 3)
```

**이 수치는 규칙을 이 표본에 맞춰 고친 뒤의 것이고, 독립적이지 않다.**
A에서 `때문`을 `WHY`에 넣은 것도 이 표본을 보고 한 일이다
(`"K02 때문에 안 되는 건가요"`가 `UNKNOWN`으로 갔다).

독립적인 수를 내려면 새 표본이 필요하다 —
`label_cli.already_labeled`가 같은 이유로 있는 장치다. 지금 말할 수 있는
것은 **"이 25건과 이 160건에서는 틀리지 않는다"**까지다.

## 남은 것

- **입원일수 축은 한 번도 발화하지 않았다**(160건 중 0). `N일 입원` 표기를
  실제 분쟁 문장이 쓰지 않는다 — "8주(56일)간의 치료", "입원하여"로 쓴다.
  이 축은 여전히 재지 못한 상태다.
- B는 **헛짚음만** 잰다. 반대 방향(실제 새 사실을 놓치는 것)은 A의 손 라벨
  5건이 전부다. 이쪽이 더 위험한 실패인데 표본이 더 적다.
- 한글 수사를 못 읽는다. `삼백만원`, `백이십만원`.
- 분류가 6종뿐이다. "다른 상품이었으면 어땠나" 같은 가정 질문(`WHAT_IF`)은
  분류에도 처리에도 없다.

## 돌리기

```
uv run python -m clausegraph.goldset.followup_eval
uv run pytest tests/test_followup_eval.py -q   # 평가셋이 분류를 다 덮는지
```

평가셋 자체도 테스트로 묶었다. 분류를 하나 늘려 놓고 문항을 안 늘리면 그
분류는 **한 번도 재지 않은 채** 전체 정확도 뒤에 숨는다.

# 042 — 이력서·경력기술서에 쓸 근거

SK주식회사(AX) AI Biz. Innovation팀 **AI Agent 개발자** 지원용. 마감
2026-11-20.

이 노트는 **다른 세션에서 이력서를 조립할 때 입력으로 쓴다.** 그래서
문장을 다듬지 않고 근거와 수치만 정확히 적는다.

## 쓰는 방법

- 왼쪽이 공고 문구, 가운데가 clausegraph의 **사실**, 오른쪽이 **쓸 수 있는 수치**
- 수치는 전부 이 리포에서 실제로 잰 것이고 노트 번호가 근거다
- **`없음`으로 적힌 것은 이력서에 쓰지 않는다.** 맨 아래 "쓰면 안 되는 말"을 볼 것
- 이 프로젝트는 **포트폴리오이고 운영된 적이 없다.** 어떤 문장도 "운영했다"로
  쓰면 안 된다

### 업무 요건을 Agent 구조로 설계 (역할·책임 분해, 테스크 흐름)

**있음.** 지급심사를 5역할로 분해했다 — 사실추출 → 보장탐색 → 면책검증 →

안전장치**다(버전을 못 정하면 보장을 찾을 수 없고, 보장이 없으면 면책을

### 프롬프트

**있음, 다만 좁다.** LLM을 쓰는 자리가 **하나뿐**이다(청구 서술 → KCD 코드).
프롬프트 엔지니어링을 넓게 했다고 쓰면 과장이다.

받은 코드를 3겹으로 거른다 — 모양 검사 / 개수 상한 / 원문 보존. **판정은
LLM이 하지 않고** 코드 범위 대조로 결정론적으로 된다.

### Tool calling

**부분.** 정직하게 갈라 써야 한다.

| 한 것 | 안 한 것 |
|---|---|
| 도구 10개를 MCP로 **정의·노출** | LLM이 도구를 고르는 **에이전트 루프** |
| 입력 스키마, 호출 시점 설명, 결과에 근거 조항 첨부 | `tool_calls` 처리 (grep 0건) |

쓰면 안 된다.** "LLM이 호출할 도구를 설계하고 노출했다"가 맞다.

### 상태/컨텍스트 관리

**있음.** 판정 뒤에 오는 말을 받는다.

핵심 판단: **multi-turn에서 위험한 것은 잊는 것이 아니라 낡은 것을 말하는
것이다.** 새 사실이 들어온 턴은 기억에서 답하지 않고 재심사로 보낸다.
*"작년에 300만원 받았는데 왜 부지급이죠"*는 `왜`가 들어 있어도 `WHY`가
아니라 `NEW_FACTS`다.

| | |
|---|---|
| 세션 수명 / 개수 / 턴 상한 | 1800초 / 64 / 40 |
| 후속 질문 분류 정확도 (내가 쓴 25문항) | 24/25 |

### 회귀 검증

**있음 (이번에 만듦).**

`eval_baselines.json` + `python -m clausegraph.regress`. 핵심 설계는
정확도가 아니라 **정직함**이었다 — 측정 대부분이 그래프·색인을 요구하는데
CI에는 없으므로 검사가 조용히 0건 돌고 초록이 되기 쉽다.

그래서 **통과 / 실패 / 못 잼** 셋으로 답하고, 못 잰 것이 있으면 맨 앞에
적는다. 방향이 있는 허용치(recall은 떨어지면 안 되고, leaks는 늘면 안 된다).

**잡는지 확인했다** — 권한 필터 한 줄을 일부러 지우니 `leaks_after_gate`가
**0 → 515**로 실패(종료 코드 1)하고 나머지 여덟 지표는 흔들리지 않았다.

⚠️ CI에서 실제로 지켜지는 것은 **구조 지표 셋뿐**이다. "CI에서 지표 회귀를
막는다"로 쓰면 과장이다.

## 우대사항

### LangChain·LangGraph 등 Agent Framework

**비교만 했다. 도입하지 않았다.** 이걸 정직하게 쓰는 것이 오히려 강하다.

같은 5단계를 LangGraph로 다시 짜고 같은 청구 195건에 둘을 걸었다. **스텝
함수를 두 벌 만들지 않아서** 다른 답이 나오면 정의상 오케스트레이션의
차이다.

| | 자체 | LangGraph |
|---|---:|---:|
| 판정 일치 | **195/195 = 100%** | |
| p50 | 0.30ms | 2.27ms |
| p95 | 4.03ms | 5.25ms |
| 의존성 트리 | 4 | **79** |

**부담은 배수가 아니라 상수다** — p50은 7.6배지만 차이는 +1.97ms로 고정이고
p95에서는 1.3배로 줄어든다. LLM을 부르는 에이전트라면 측정 한계 아래다.

안 쓰는 근거는 속도가 아니라 **이 흐름에 순환·합류·재개가 하나도 없다**는
것. 그리고 폐쇄망에 패키지 15개(그중 `langsmith`)를 들일 값어치가 없다.

**그런데 하나는 배워 왔다.** LangGraph는 종료 노드 넷이 초안만 만들고 엣지가
전부 한 노드로 모인다. 자체 구현은 종료 지점 넷이 각자 가드레일을 불렀는데
그건 **약속이지 구조가 아니다.** 단일 종료로 고쳤다 — `_finalize` 호출
지점 **4 → 1**, 판정 **195/195 그대로**.

> 쓸 문장: *"프레임워크를 도입하지 않고, 프레임워크가 강제하던 성질만
> 가져왔다 — 그 판단을 195건 판정 일치로 뒷받침했다."*

→ notes/040

### 지식그래프·온톨로지

**지식그래프 있음. 형식 온톨로지는 없음.**

Neo4j 속성그래프 — 6노드(Product·Version·Article·Item·Coverage·Provision)
× 6관계, 제약 6개. **OWL/SKOS도 추론 규칙도 없다.**

이 프로젝트에서 그래프를 쓴 진짜 이유 셋(전부 수치로 확인):

1. **면책은 부정 조건이라 벡터가 놓친다** — vector recall 32.9% vs graph 100%
2. **약관에는 시점 축이 있다** — 부칙 26건을 **적용 단위 30개**로 쪼갰고
   11개는 조문·별표 일부만 바꾼다. 적용일이 **상품마다 다르다**

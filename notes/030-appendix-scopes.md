# 030 — 부칙은 조문마다 다른 날짜를 정한다

백로그에 두 항목이 남아 있었다.

- 부칙의 **조문 단위 한정** (`생명보험 표준약관 제7조 …`)
- 부칙의 **다중 날짜** — 날짜 후보가 여럿이면 판정하지 않고 넘겼다

부칙 26건을 다시 읽으니 **둘이 같은 문제**였다.

## 날짜가 여럿인 이유

```
다만 [별표 15]의 <자동차보험> 제9조, 제11조의 개정사항은 2020년 10월 22일부터
시행하고, [별표 15]의 <자동차보험> 제1조, 제20조, 제27조, <별표1>, <별표2>의
개정사항은 2020년 11월 10일부터 시행한다.
```

날짜가 둘인 것은 애매해서가 아니다. **조문마다 시행일이 다르기 때문**이다.
`제9·11조`는 10월 22일, `제1·20·27조`는 11월 10일.

그래서 `applies_to_enrollment`는 이걸 "판정할 수 없다"로 넘겼다. 판정할 수
없는 것이 아니라 **하나로 묶어 보고 있었다.**

## 날짜 단위로 쪼갠다

부칙 본문을 날짜에서 끊는다. 각 조각이 그 날짜에 걸리는 상품과 조문을
자기 안에 들고 있다.

```python
@dataclass(frozen=True)
class Scope:
    applies_on: str
    new_contracts_only: bool
    products: tuple[str, ...] = ()      # 비어 있으면 별표15 전체
    articles: tuple[str, ...] = ()      # 비어 있으면 그 상품 전체
    tables: tuple[str, ...] = ()
    excludes_articles: bool = False
```

부칙 26건이 **적용 단위 30개**로 갈렸다.

| | |
|---|---|
| 상품 전체에 걸리는 단위 | 19 |
| **조문·별표 일부만** 바꾼 단위 | **11** |

## 조문을 뽑는 데 함정이 셋 있었다

### 1. 부칙이 자기 조문을 가리킨다

```
제2조(적용례) 제1조에도 불구하고 [별표15] 표준약관 개정내용은 …
```

`제2조`는 **부칙의** 조문 제목이고 `제1조`는 부칙 제1조(시행일)다. 이걸
표준약관 조문으로 읽으면 **거의 모든 부칙이 "제1·2조가 바뀌었다"고 말한다.**

부칙 자기 조문의 표기는 셋이다 — `제N조(적용례|경과규정|…)`, `제N조에도`,
`부칙 제N조`. 조문을 뽑기 전에 지운다.

### 2. 세칙 조문이 섞여 있다

```
별표 15 표준약관(제5-13조제1항관련) 손해보험 <자동차보험> 제11조의 개정내용은 …
```

`제5-13조`는 **별표15를 달고 있는 세칙 조항**이다. 표준약관 조문은 제11조
하나다. 하이픈이 든 조문 번호를 세칙 조문으로 보고 뺀다.

### 3. 별표15의 표기가 세 가지다

```
별표15    [별표 15]    <별표 15>
```

닫는 괄호를 허용하지 않는 정규식은 `[별표 15] 실손의료보험 표준약관`에서
상품을 놓친다. **그러면 조문 단위 한정이 상품 전체로 읽힌다** — 정확히
반대 방향의 오류다.

## 조문 일부만 바꾼 부칙으로는 버전을 옮기지 않는다

이게 이번 작업의 핵심 판단이다.

`제11조`만 2022-07-28부터 시행된다면, 2022-07-01 가입자에게 그 조문은 옛
내용이고 나머지는 새 내용이다. **한 계약에 두 판본이 걸린다.**

이 그래프는 조문을 판본에 매어 두었다(notes/006). 조문 단위 판본이 없으니
"제11조만 옛 것"을 표현할 수 없다. 그렇다고 버전 전체를 옮기면 **그 상품의
나머지 조문까지 끌려간다** — 조용히 틀린 약관을 들이대는 쪽이다.

그래서 옮기지 않는다. 대신 **그런 부칙이 있다는 사실을 노드에 남긴다.**

```
Provision.article_scoped         조문·별표 일부만 바꿨는가
Provision.article_scope_notes    적용 단위마다 한 줄
Provision.article_scope_products 그 단위의 상품 (같은 순서)
```

노트와 상품을 **적용 단위마다 따로** 담는다. 하나로 뭉치면 자동차보험 조문
개정이 실손 조회에도 딸려 나온다 — 처음에 뭉쳐 두었다가 실제로 그렇게 됐다.

## 답에 실어 준다

`resolve_terms_version`이 판본만 말하고 끝내면, 그 안에서 조문 몇 개는 아직
옛 내용이라는 사실이 사라진다.

```
가입일 2026-05-20 / 자동차보험 -> 적용 약관 20250901
주의: 세칙 시행일자로만 보면 20260506이지만, 부칙이 이 상품의 약관 적용일을
      따로 정해 20250901이 적용된다.
주의: 이 판본에는 **조문 일부만** 시행일을 따로 정한 부칙이 있다. 아래 조문을
      인용할 때는 그 시행일을 함께 확인해야 하고, 단정하지 말고 심사자
      확인이 필요하다고 전할 것.
  공포 20211227 — 2022-07-28 자동차보험 제11조
  공포 20211227 — 2023-01-01 자동차보험 별표1·3
  공포 20201016 — 2020-10-22 자동차보험 제9·11조
  공포 20201016 — 2020-11-10 자동차보험 제1·20·27조 별표1·2
  공포 20180525 — 2018-05-29 자동차보험 제11조
  공포 20121228 — 2013-07-01 자동차보험 제12·13·15·16·18·20·21·24조
```

같은 가입일로 상품만 바꾸면 목록도 바뀐다.

```
가입일 2026-05-20 / 생명보험 -> 적용 약관 20250901
  공포 20100129 — 2011-04-01 생명보험,질병ㆍ상해보험 제7조

가입일 2026-05-20 / 기본형 실손의료보험(급여 실손의료비) -> 적용 약관 20260506
  공포 20170322 — 2017-04-01 실손의료보험,해외여행 실손의료보험 제4조
  공포 20151130 — 2009-10-01 실손의료보험 제2·4조
  …
```

**자동차보험 조문 개정이 실손 조회에 나오지 않는다.** 그게 이 작업의 목표였다.

## 아직 모델링하지 않은 것

부칙 하나가 **체결 기준일과 적용 기준일을 한 문장에** 담는 경우가 있다.

> ② … [별표 15]의 개정사항 중 '…'을 제외한 개정사항은 **2009년 10월 1일**
> 이후에 신규로 체결된 실손의료보험 계약에 대해서도 **2019년 1월 1일**부터
> 적용한다.

2009-10-01은 계약 체결 기준, 2019-01-01은 적용 기준이다. 날짜에서 끊으면
상품도 조문도 없는 조각이 생기는데, 그건 새 적용 단위가 아니라 앞 문장의
이어짐이다. **별표15를 가리키지 않는 조각은 버린다.**

그러면 앞 단위의 날짜(2009-10-01)만 남고 적용 기준일(2019-01-01)이 사라진다.
26건 중 이런 문장은 하나뿐이고 2009년 계약을 다루므로, 수집 범위(2025년
이후) 밖이다. 억지로 모델링하지 않고 여기 적어 둔다.

## 배운 것

**"판정할 수 없다"가 답인 경우와 아직 안 본 경우는 다르다.**

`applies_to_enrollment`는 날짜가 여럿이면 `None`을 냈고, 그건 정직한 처리로
보였다. 실제로는 **왜 여럿인지를 안 본 것**이었다. 이유를 보니 조문마다
날짜가 다른 것이었고, 쪼개고 나면 19개 단위는 그냥 판정된다.

notes/018·019·022·025에서 되풀이한 것과 같다 — 숫자나 상태를 얻은 자리에서
멈추지 말고 그것이 **왜 그런지** 원문을 봐야 한다. 이번에는 그 대상이
`None`이었다.

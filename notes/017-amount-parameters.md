# 017 — 금액산정 파라미터를 약관에서 확정했다

> **정정 (notes/019)**
>
> 이 노트의 보상비율과 데모 출력은 틀렸다.
>
> 1. **보상비율은 입원에만 붙는다.** 여기서 "특약1 보상비율 70%"라고 적은
>    것은 제3조 표의 **입원 행** 값이다. 같은 표의 통원 행은 공제금액을 뺀
>    금액 자체를 보상금액으로 정하고 비율을 걸지 않는다. 통원에 입원 비율을
>    곱해 최대 2배 과소지급했다.
> 2. **표준약관에는 감액기간 규정이 없다.** 아래 데모 출력의
>    "감액기간(730일) 안이라 50%"는 근거 없는 감액이었다. CLM-006의 실제
>    지급액은 60만원이 아니라 **120만원**이다.
>
> 아래 본문은 기록으로 남겨 둔다. 확정된 값은 notes/019를 보라.

## 문제

금액산정 에이전트는 W3부터 있었지만 **파라미터가 비어 있었다**(notes/014).
`annual_limit=None`, `outpatient_deductible=None`이면 계산기가 계산했다고
말하지 않고 가드레일이 `HUMAN_REVIEW`로 넘긴다. 안전하지만, 실손 청구가
전부 사람에게 넘어가면 자동 심사라고 할 수 없다.

특히 **비급여 특약의 값을 하나도 몰랐다.** 급여 실손은 채워져 있었는데
특약1·2는 비율만 있고 한도와 공제가 비어 있었다.

## 읽은 것

최신 판본(20260506)의 특약1·2 **제5조(보험가입금액 한도 등)**와
**제3조 `<표1>`**을 직접 열었다. 추측하지 않았다.

### 특약1(중증 비급여) — 자기부담 30%

| 항목 | 값 | 근거 |
|---|---|---|
| 연간 한도 | 상해비급여 5천만원, 질병비급여 5천만원 | 제5조 ① |
| 통원 1회당 한도 | 20만원 | 제5조 ③ |
| 통원 횟수 한도 | 연 100회 | 제5조 ③ |
| 통원 공제 | **3만원과 보장대상 의료비의 30% 중 큰 금액** | 제3조 `<표1>` |

### 특약2(비중증 비급여) — 자기부담 50%

| 항목 | 값 | 근거 |
|---|---|---|
| 연간 한도 | 상해비급여 1천만원, 질병비급여 1천만원 | 제5조 ① |
| 통원 1일당 한도 | 20만원 | 제5조 ③ |
| 통원 일수 한도 | 연 100일 | 제5조 ③ |
| 통원 공제 | **5만원과 보장대상 의료비의 50% 중 큰 금액** | 제3조 `<표1>` |

**중증과 비중증의 격차가 크다.** 연간한도는 5배(5천만 대 1천만), 통원 공제는
정액도 비율도 1.7배 차이가 난다. 비급여를 중증·비중증으로 가르는 것이
5세대 실손 개편의 핵심이고, 그 결과가 이 숫자에 다 들어 있다.

## 코드 변경

### 통원 1회당 한도가 새 축이었다

기존 계산기는 `공제 → 보상비율 → 감액 → 연간한도` 네 단계였다. 그런데
특약의 "통원 1회당 20만원 이내"는 **연간한도와 별개로** 걸린다. 축을 하나
추가했다(`AmountRule.outpatient_visit_limit`).

순서가 중요하다. 보상비율을 곱한 **뒤에**, 감액을 곱하기 **전에** 건다.

```
공제 → 보상비율 → [통원 1회 한도] → 감액기간 → 연간한도 잔액
```

입원에는 걸지 않는다 — 조문이 통원에만 정한 한도다.

### 왜 아직도 손으로 적는가

값을 손으로 적되 **읽은 조항의 uid를 함께 적는다**(`source_articles`).
자동 파싱을 하지 않는 이유는 notes/014에 쓴 그대로다: 값이 표 안의 표에
중첩되고 다른 조항을 참조하며, 정규식으로 긁으면 조용히 틀린 숫자가 나온다.
**틀린 숫자는 곧 틀린 지급액이다.**

값은 판본당 한 번 바뀌고 몇 개뿐이다. 사람이 근거 조항을 열어 대조할 수
있는 형태가 자동 파싱보다 안전하다.

## 여전히 비워 둔 것

- **3대비급여·비급여 MRI**는 제3조가 항목별로 따로 한도를 정한다. 하나의
  비율·한도로 요약할 수 없어 규칙을 넣지 않았다. 규칙이 없으면 계산하지
  않고 사람에게 넘어간다.
- **통원 연 100회/100일 한도**는 계약별 누적 횟수를 저장해야 판정할 수
  있다. 지금 구조에 그 상태가 없다.
- **급여 통원 공제의 의료기관 종류별 차등**은 최소 유형(1만원/20%)만
  반영했다. 상급종합병원은 더 크다.

세 가지 모두 `note`에 적어 두었다. 비워 둔 것을 비워 둔 채로 두고 사람에게
넘기는 것이, 추측한 값으로 지급액을 내는 것보다 낫다.

## 측정

데모에 지급액이 실제로 나오는 경로 둘을 추가했다.

**CLM-006** 급여 실손 / 폐렴(J18) 6일 입원 / 150만원 청구

```
보상비율 80% / 가입 후 506일 — 감액기간(730일) 안이라 50%
  / 연간한도 잔액 50,000,000원 이내
-> PARTIAL  600,000원
```

**CLM-007** 특약1 / 유방암(C50) 비급여 항암 통원 / 100만원 청구

```
통원 공제 300,000원(정액과 비율 중 큰 쪽) / 보상비율 70%
  / 통원 1회 한도 200,000원으로 제한
  / 가입 후 80일 — 감액기간(730일) 안이라 50%
  / 연간한도 잔액 50,000,000원 이내
-> HUMAN_REVIEW  0원  (가드레일 uncertain_exclusion)
```

CLM-007이 이 프로젝트의 구조를 한 화면에 보여준다. **계산은 끝까지
됐다**(10만원). 그런데 면책 70건 중 불확실 히트가 1건 남았고, 가드레일이
그 상태로는 지급하지 않는다(notes/012). 계산기와 가드레일이 서로 독립이라
"금액은 이렇게 나오지만 지급하면 안 된다"를 말할 수 있다.

## 덤으로 잡힌 것

CLM-007을 처음에 가입일 2025-04-01로 넣었더니 **보장 조항 0개**가 나왔다.

방향도 같다. 상품은 판본마다 생기고 사라진다. 가입일로 버전을 고정하는
설계가 이걸 그냥 맞게 처리한다.

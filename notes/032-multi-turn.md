# 032 — multi-turn: 기억을 두되 낡은 채로 말하지 않기

지금까지 이 시스템은 **단발 판정기**였다. 청구를 넣으면 판정이 나오고 끝난다.
실제 창구는 그렇게 끝나지 않는다.

    "왜 안 되는데요"
    "뭘 내면 되나요"
    "작년에 받은 게 있는데 그럼 달라지나요"

세 번째가 앞의 둘과 질이 다르다. 앞의 둘은 **같은 판정을 설명**하는 말이고,
세 번째는 **판정의 입력을 바꾸는** 말이다. 이 둘을 가르지 못하면 multi-turn은
기능이 아니라 사고다.

## 무엇을 기억하는가

대화 글이 아니라 **판정의 구조**를 기억한다. `Claim`과 `Adjudication`이고
둘 다 frozen이다. 후속 질문은 그 구조에서 결정론적으로 답한다.

앞 턴의 **답변 문장**을 들고 다니면서 거기에 이어 말하는 방식을 쓰지 않았다.
두 턴만 지나면 인용이 원본에서 떠내려가기 때문이다 — 이 저장소가 notes/020에서
인용 무결성에 들인 것을 대화 층에서 도로 잃게 된다.

    턴1 답변:  "치과치료(K00~K08)에 걸립니다"
    턴2 답변:  "앞서 말씀드린 치과 관련 면책 때문에…"
    턴3 답변:  "치과 쪽 규정상…"          <- 조항이 사라졌다

구조에서 답하면 턴이 몇 개든 인용은 `20260506/…/제4조#(3)` 그대로다.

## 낡은 답 — 이 층에서 가장 나쁜 실패

```
턴1  "충치 임플란트 120만원"        -> DENIED  (근거: 치과치료 K00~K08)
턴2  "아 작년에 이미 300만원 받았어요"
```

턴2를 "왜"로 읽으면 **이미 낡은 판정에 근거 조항까지 붙여 자신 있게** 설명한다.
근거가 붙어 있어서 더 설득력 있고, 그래서 더 나쁘다.

그래서 새 사실 검사가 **다른 모든 분류보다 먼저** 온다.

| 질문 | 분류 | 왜 |
|---|---|---|
| "왜 부지급이죠" | `WHY` | 판정을 설명하는 말 |
| "작년에 300만원 받았는데 **왜** 부지급이죠" | **`NEW_FACTS`** | `왜`가 있어도 입력이 바뀐다 |
| "120만원이 왜 안 나와요" | `WHY` | 120만원은 **이미 아는 값**이다 |
| "S82 골절도 같이 있었어요" | `NEW_FACTS` | 모르던 코드 |
| "2026-07-01 가입 맞습니다" | `WHY`/`UNKNOWN` | 아는 날짜를 확인해 준 것 |

**숫자가 있다고 새 사실이 아니다.** 지금 아는 값과 **달라야** 센다. 이걸
빠뜨리면 사용자는 같은 답을 두 번 받으면서 매번 "다시 심사했습니다"를 듣는다.

새 사실이면 답하지 않고 `revise_claim`으로 보낸다. 거기서 **다시 심사하고
앞 판정과의 차이를 낸다.**

    다시 심사한 결과: 판정 DENIED -> HUMAN_REVIEW / 걸린 가드레일 amount_upper_bound

## 분류는 규칙으로 한다

질문 분류에 LLM을 쓰지 않았다. notes/031에서 본 대로 이 규모에서는 규칙이
더 빠르고 틀리는 방식이 예측 가능하다. 무엇보다 **못 알아들었을 때 지어내지
않는다.**

`UNKNOWN`은 정직한 답이고, 그때는 대화가 들고 있는 것을 보여 준다.

```
무엇을 묻는지 가리지 못했다. 지어내 답하지 않는다.
지금 대화가 들고 있는 것: 실손의료보험 특별약관1 / 가입 2026-07-01 / 판정 DENIED
판정 이유·근거 조항·필요 서류·지급액 중에서 물어볼 것.
```

## 부지급에 "서류를 내면 된다"고 답하지 않는다

`DOCS` 질문의 답은 판정마다 다르다. 여기서 한 줄로 뭉개면 청구인을
헛걸음시킨다.

| 판정 | 답 |
|---|---|
| `NEEDS_DOCS` | 무엇이 없어서 못 정했는지 이름으로 |
| `HUMAN_REVIEW` | 기계가 정할 일이 아니라고 넘긴 건이다 + 발동한 가드레일 |
| `DENIED` | **서류로는 뒤집히지 않는다.** 면책에 걸린 것이다 |
| `PAID`/`PARTIAL` | 더 받을 서류 없음 |

다만 `DENIED`에서 끊지 않는다. 면책의 상당수가 `다만`으로 예외를 달고 다른
조문을 가리킨다(notes/022). 그 예외 근거가 있으면 함께 짚는다.

```
부지급은 서류가 없어서가 아니라 약관 면책에 걸려서다. 서류를 더 낸다고
뒤집히지 않는다.
다만 이 면책에는 예외가 달려 있다 — 해당되는지 확인할 것:
  제3조(보장종목별 보상내용) 안면부 골절로 발생한 의료비는 보상합니다
```

## 기억의 수명

세션은 프로세스 안에 둔다. 폐쇄망 전제라 외부 세션 저장소를 가정하지 않고,
심사 한 건이 0.7ms라 왕복 비용이 측정 대상보다 커진다(observability.py와
같은 판단이다).

그래서 상한을 건다.

| | 값 | 왜 |
|---|---|---|
| 수명 | 30분 | 어제 하던 이야기에 오늘 이어 답하면 그 사이 바뀐 것을 모른다 |
| 동시 대화 | 64 | 없으면 프로세스가 대화를 영원히 들고 있는다 |
| 턴 | 40 | 이보다 길면 새 청구로 시작하는 게 맞다 |

만료된 세션은 **되살리지 않는다.** 없으면 없다고 말하고 처음부터 시작하게
한다.

판정은 갈아 끼우지 않고 **판(revision)을 올린다.** 어느 판을 근거로 답했는지
되짚을 수 있어야 한다 — 턴마다 그때의 판 번호가 붙어 있다.

## 재심사에서 값을 덮지 않는다

`revise_claim`은 **준 값만** 갈아 끼운다. 음수는 "주지 않았다"이고 0은
"올해 아무것도 없다"다(notes/027과 같은 규약).

통원 횟수만 말하려던 사람이 기지급액을 0으로 만들면, 한도가 되살아나
**조용한 과다지급**이 된다. 테스트로 고정했다.

서술이 새로 오면 사실추출을 **다시** 돌린다. 앞의 코드에 덧붙이지 않는다 —
청구인이 고쳐 말한 것이면 취소한 진단이 면책을 계속 걸면 안 된다.

## 알려진 한계 — 부정을 읽지 못한다

재심사는 사람이 "**아니라**"라고 말하는 자리인데, 용어집은 낱말만 본다.

> "충치가 **아니라** J18 폐렴이었습니다" → `K02`(충치)가 그대로 붙는다

즉 **고쳐 말할수록 옛 진단이 따라붙는다.** 원래 있던 약점인데
(`agents/terminology.py`는 부정을 모른다) multi-turn이 그 약점을 가장
자주 밟는 경로를 만들어 낸 셈이다.

지금은 고치지 않고 **테스트로 고정**해 뒀다
(`test_negation_in_a_revision_is_not_understood`). 고친 줄 알고 넘어가지
않기 위해서다. 제대로 고치려면 부정 범위를 읽어야 하고, 그건 규칙으로
감당이 안 되는 자리다 — notes/031이 남긴 "선택 방식 LLM을 불확실 버킷으로"
조건이 걸리는 자리이기도 하다.

이 한계 때문에 `revise_claim`에 `narrative`를 줄 때는 **고친 뒤의 문장만**
주는 것이 맞다. 도구 설명에 적어 두지 않았다 — 다음 판에서 채운다.

## 범위

- 대화 상태는 **프로세스 안**이다. 서버를 다시 띄우면 사라진다.
- 분류는 규칙 기반이고 **평가셋이 없다.** 위 표의 예시는 테스트로 고정돼
  있지만 실제 청구인 말투 분포로 재지 않았다. Tier B의 분쟁 서술로
  분류 정확도를 재는 것이 다음 일이다.
- 새 사실 검사는 금액·코드·일수·일자 네 가지만 본다. 의료기관 종류나
  본인부담률이 뒤늦게 나오는 경우는 잡지 못한다.
- 동시 접속을 가정하지 않았다. 단일 프로세스 stdio MCP 서버 전제다.

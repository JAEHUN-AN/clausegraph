# 022 — 참조를 엣지로 만들다가 조문 60개가 사라진 걸 찾았다

## 왜 참조인가

notes/020에서 면책 항목 안의 조문 상호참조 때문에 인용문이 망가진 것을
고쳤다. 그 과정에서 그 참조들이 무엇을 가리키는지 읽게 됐다.

> 산재보험에서 보상받는 의료비. **다만**, 본인부담의료비(…)는
> **제3조(보장종목별 보상내용) (2)질병급여 제1항 및 제3항부터 제8항에 따라
> 보상합니다.**

**면책이면서 동시에 보상의 근거를 가리킨다.** 참조를 따라가지 않으면
"면책에 걸렸다"까지만 말하고 끝난다. 청구인에게는 그 뒤가 중요하다.

벡터 검색으로는 이 연결을 만들 수 없다. `제3조`라는 표기는 어떤 청구
문장과도 닮지 않았고, 가리키는 대상은 **같은 판본·같은 상품의** 제3조여야
한다. 판본 4개 × 상품 16개면 같은 '제3조'가 예순 개가 넘는다.

## 먼저: 약관 안과 밖을 가른다

`제N조` 표기가 3,881번 나온다. 그중 **42%가 약관 밖**을 가리킨다.

```
「국민건강보험법」 제42조          법령 이름이 앞에 붙는다
?금융소비자 보호에 관한 법률?제47조   원문에서 괄호가 ? 로 깨진 표기
동법 제3조의3                     앞서 든 법을 다시 가리킨다
민법 제768조                      법명이 짧아 「」 없이 쓴다
보건복지부 고시 제148조             법이 아닌 고시
```

외부 참조를 내부로 잘못 읽으면 **번호만 같은 엉뚱한 조문에 엣지가 생긴다.**
그래서 앞을 보고 판정하고, 판정하지 못하면 엣지를 만들지 않는다.

두 가지가 판정을 어렵게 했다.

**1. 나열** — 법령 이름은 첫 항에만 나온다.

```
「국민건강보험법」제5조, 제53조, 제54조
「…요양급여의 기준에 관한 규칙」 제11조제1항 또는 제13조제1항
```

앞의 참조가 외부였고 그 사이가 이음매(`, · 또는 및 제N항`)뿐이면 이어받는다.

**2. 표 셀** — 조문이 표 안에 있으면 법령 이름과 참조 사이에 괘선이 끼어든다.

```
「의료급여법 시행령」 ┃  ┃  ┃ 제13조 및 별표1에 따라
```

앞을 볼 때 괘선을 먼저 지운다. 이걸 안 하면 표 안의 외부 참조가 전부
내부로 읽힌다.

### 결과

| | |
|---|---|
| `제N조` 표기 | 3,881 |
| 외부 법령 참조 | 1,619 (41.7%) |
| 약관 내부 참조 | 2,262 |
| **해석됨** | **98.3%** |
| 해석 안 됨 | 28 (1.7%) |

남은 28개는 표 셀 안의 외부 법령 참조인데 법령 이름이 앞 셀에 있어
40자 안에 안 들어온다. **엣지를 만들지 않고 센다** — 적재 로그에
`참조 412(미해석 8)`로 찍힌다. 못 만든 엣지의 수를 로그에 남기지 않으면
다음에 파서가 나빠져도 모른다.

## 중간에 나온 것: 조문 60개가 없었다

참조 해석률을 처음 재니 80.5%였다. 미해석 상위를 보다가 이상한 걸 봤다.

```
급여 실손 조문 번호: 1, 2, 3, 4, 4의2, 5의2, 5, 6, … 24, 25, 26, 30, 31의2, …
```

**26 다음이 30이다.** 제27·28·29조가 없다. 그런데 다른 조문이 그걸 가리킨다.
원문을 열었다.

```
제26조(보험료의 자동대출납입) ① 계약자는 제27조…
제27조[보험료의 납입이 연체되는 경우 납입최고(독촉)와 계약의 해지] ① …
제28조[보험료의 납입연체로 인한 해지계약의 부활(효력회복)] ① …
제29조[강제집행 등으로 인한 해지계약의 특별부활(효력회복)] ① …
제30조(보험료의 계산) ① …
```

**제목을 대괄호로 묶었다.** 제목 안에 `납입최고(독촉)`처럼 괄호가 들어가니
겹치지 않게 바깥을 대괄호로 바꾼 것이다.

조문 파서의 정규식은 소괄호만 인정했다.

```python
_ARTICLE_RE = re.compile(r"^\s*제\s?(\d+)\s?조(?:의\s?(\d+))?\s*\(([^)]*)\)\s*(.*)$")
```

그래서 이 세 줄은 조문 머리글로 인식되지 않고 **앞 조문의 본문에 붙었다.**

그리고 같은 정규식에 **두 번째 버그**가 있었다. `[^)]*`는 첫 `)`에서 멈춘다.

```
제26조(보험료의 납입이 연체되는 경우 납입최고(독촉)와 계약의 해지)
  -> 제목 "보험료의 납입이 연체되는 경우 납입최고(독촉"
     본문 "와 계약의 해지) ① 계약자가 …"
```

**제목이 잘리고 남은 조각이 본문 앞에 붙었다.**

판본 파일 10개에서 센 규모다.

| | |
|---|---|
| 조문 머리글 | 4,478 |
| 대괄호 제목 -> **통째로 누락** | **60** |
| 제목이 잘린 것 | **60** |

### 고친 방법

정규식으로 균형 괄호를 세려 하지 않았다. **번호만 정규식으로 잡고, 제목은
여는 괄호의 짝을 찾을 때까지 깊이를 센다.**

```python
_ARTICLE_HEAD_RE = re.compile(r"^\s*제\s?(\d+)\s?조(?:의\s?(\d+))?\s*(?=[(\[])")
_TITLE_BRACKETS = {"(": ")", "[": "]"}
```

짝이 그 줄에서 닫히지 않으면 조문 머리글로 보지 않는다. 제목이 여러 줄로
넘어가는 경우는 없었고, 추측해서 자르면 제목과 본문이 섞인다.

| | 전 | 후 |
|---|---:|---:|
| 조문 | 1,774 | **1,798** |
| 제목이 잘린 조문 | 60 | **0** |
| 참조 해석률 | 80.5% | **98.3%** |

## 엣지

```
(:Article|:Item)-[:REFERS_TO {in_proviso}]->(:Article)
```

**같은 판본·같은 상품 안에서만 잇는다.** 번호만 맞는 다른 상품의 조문에
이으면 조용히 틀린 근거를 낸다 — 같은 '제3조'가 상품마다 전혀 다른 내용이다.

`in_proviso`는 그 참조가 `다만` 뒤에 있다는 뜻이다. 전체 참조의 **40.3%**가
여기 해당한다. 면책의 예외가 보상 조문을 가리키는 자리가 그곳이다.

1,592개 엣지가 적재됐다.

### 표에서 뽑은 면책 사유를 빼먹었다

처음 적재하고 세 보니 **면책 호의 예외 참조가 0개**였다. 앞서 116개를
셌는데 0이 나왔다.

참조 추출이 `article.paragraphs`만 훑고 있었다. 실손 계열은 면책을
**보장종목별 표**로 적으므로 그 사유가 `paragraphs`에 없다 — 표 파서가
따로 뽑아 넣는다(notes/007). **정작 예외가 제일 많은 자리를 빼먹었다.**

표 항목을 함께 넘기고 나서:

| | |
|---|---|
| Item -> Article 참조 | 464 |
| 그중 '다만' 뒤 | 152 |
| **예외 참조가 붙은 면책 호** | **116 / 1,446 (8.0%)** |

## 쓰는 자리

면책에 걸리면 그 면책의 예외가 가리키는 조문을 **근거로 함께 낸다.**
확실한 부지급에도, 사람에게 넘기는 불확실 히트에도 붙인다 — 심사자는
"이 면책이 걸릴 수도 있다"와 "그런데 예외가 있다"를 함께 봐야 한다.

**CLM-009** 급여 실손 / 교통사고 3일 입원 / 자동차보험에서 치료관계비 일부 수령

```
CLM-009  ->  HUMAN_REVIEW   지급액 0원
사유: 확인하지 못한 면책 가능성이 남아 있다 — 심사자 확인이 필요하다
가드레일: uncertain_exclusion

--- 근거 ---
[coverage]  제1조(보장종목)
[coverage]  제3조(보장종목별 보상내용)
[exclusion] 제4조(보상하지 않는 사항)
    자동차보험(공제를 포함합니다)에서 보상받는 치료관계비(과실상계 후 …)
    또는 산재보험에서 보상받는 의료비. 다만, 본인부담의료비(…
[exclusion] 제4조(보상하지 않는 사항)
    산재보험에서 보상받는 의료비. 다만, 본인부담의료비(…)는 제3조…
[exception] 제3조(보장종목별 보상내용)
    회사가 이 계약의 보험기간 중 보장종목별로 각각 보상하거나 공제하는
    내용은 다음과 같습니다. …(표)
```

`[exception]`이 붙은 것이 이번에 생긴 것이다. 자동차보험에서 치료관계비를
받았으니 면책이 걸리는데, **본인부담의료비는 제3조에 따라 보상한다.**
심사자가 확인할 것이 "지급이냐 부지급이냐"가 아니라 "본인부담의료비가
얼마냐"로 좁혀진다.

## 배운 것

**참조 해석률이 파서 검사기였다.** 80.5%라는 숫자 자체가 목표가 아니었는데,
그 20%를 들여다보다가 조문 60개가 없어진 걸 찾았다. 조문이 사라진 것은
조문 수를 세도 안 보인다 — 1,774개가 맞는지 알 방법이 없었다. **약관이
자기 자신을 가리키는 것을 이용해서야 빈칸이 드러났다.**

그리고 018·019·020에 이어 또 같은 모양이다. 018은 표의 한 칸만 읽어서,
019는 한 행만 읽어서, 020은 정규식이 무엇을 지우는지 안 봐서, 이번은
**정규식이 무엇을 못 읽는지 안 봐서** 틀렸다. 넷 다 "찾던 걸 찾은 순간
멈췄다"가 원인이다.

이번에는 멈추지 않는 장치가 하나 생겼다 — 적재 로그의 `미해석 N`. 약관이
스스로 가리키는 곳을 못 찾으면 그 수가 늘어난다.

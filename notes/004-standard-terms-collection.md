# 004 — 시행일자별 표준약관 수집

`보험업감독업무시행세칙` 본문 XML의 `<별표내용>`에서 별표15(표준약관)를
꺼내 시행일자별로 모은다. HWP 첨부는 쓰지 않는다 — 이유는 notes/003 정정.

## 결과 (최근 10개 개정)

```
uv run python -m clausegraph.law.collect --limit 10
```

| 시행일자 | 문자 수 | 구분 |
|---|---|---|
| 20260910 | 797,517 | 현행 |
| 20260715 / 20260630 / 20260506 | 796,875 | 연혁 |
| 20260301 / 20251231 / 20251028 / 20250901 | 614,757 | 연혁 |
| 20250611 / 20250401 | 613,116 | 연혁 |

세칙 개정은 총 **184건**(현행 1 + 연혁 183) 확인.

## 세칙 개정 ≠ 약관 개정

가장 중요한 발견이다. **개정 10건이 실제로는 표준약관 4개 버전이었다.**
세칙은 별표가 100개 넘게 붙은 큰 문서라, 다른 별표만 바뀌고 별표15는
그대로인 개정이 많다.

| 적용 구간 | 문자 수 | 세칙 개정 |
|---|---|---|
| 20260910 ~ 현재 | 797,517 | 1건 |
| 20260506 ~ 20260910 | 796,875 | 3건 |
| 20250901 ~ 20260506 | 614,757 | 4건 |
| 20250401 ~ 20250901 | 613,116 | 2건 |

그래서 수집기는 내용 SHA-256으로 연속 개정을 묶고 각 버전에
`[effective_from, effective_to)` 구간을 매긴다. 그래프의 버전 노드는
**약관이 실제로 바뀐 시점**이어야지 세칙 개정마다 만들면 안 된다.

내용이 A → B → A로 돌아오는 경우도 구간 셋으로 잡는다(테스트로 고정).

## 2026-05-06에 무슨 일이 있었나

614,757자 → 796,875자, **18만 자가 늘었다.** 섹션 목록을 보면 원인이 보인다.

- 2025~2026.03: `실손의료보험 특별약관(비급여 실손의료비)` 1개
- 2026.05 이후: `특별약관1(중증 비급여)` + `특별약관2(비중증 비급여)`로 분리,
  해외여행 실손도 같은 방식으로 분리

5세대 실손 개편이다. **같은 "실손의료보험 특별약관"이라는 이름이 가입
시점에 따라 다른 문서를 가리킨다** — 프로젝트가 주장하는 시점 축이
추상론이 아니라는 증거다.

## 부칙이 적용 시점을 따로 정한다

수집 중에 부칙에서 이런 문장을 봤다.

> 이 세칙 개정내용 중 [별표14] 표준사업방법서 및 [별표 15] 표준약관
> 개정내용은 **2018년 4월 1일부터 신규로 체결되는 계약부터** 적용한다.

즉 **세칙 시행일 ≠ 약관 적용일**이고, 적용 대상도 "신규 계약부터"로 한정된다.
지급 판정에서 "이 계약에 어느 약관이 적용되는가"를 정하려면 시행일자만으로는
부족하고 부칙의 적용례를 함께 읽어야 한다. 그래프 스키마에 반영할 것.

## 용량

본문 XML은 한 건에 4~5MB다(10건 = 44MB). 약관 텍스트만 남기면 13MB.
`--drop-xml`로 캐시를 지울 수 있게 했다. `data/law/`는 git에서 제외하고
`manifest.json`만 남긴다.

184건 전부 받으면 XML 트래픽이 800MB 안팎이므로, 파서를 세운 뒤 필요한
구간만 넓히는 게 낫다.

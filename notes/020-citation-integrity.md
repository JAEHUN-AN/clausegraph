# 020 — 부지급 근거로 "보상합니다"를 인용하고 있었다

README 예시가 낡았는지 확인하려고 그 문장을 그대로 돌려 봤다. 판정은 맞았고
근거 조항 uid도 맞았다. 그런데 인용문이 이랬다.

```
근거  …/제4조#(3)3대비급여#4-1
      제4조(보상하지 않는 사항) 에 따라 보상합니다)
```

**부지급 결론의 근거로 "보상합니다"를 인용했다.**

## 항목은 온전했다

먼저 데이터를 의심했다. 해당 상품의 면책 항목 27개를 다 찍어 봤더니
전부 정상이었다. `#4-1`은 139자짜리 온전한 문장이다.

> 치과치료(K00∼K08, 다만, 안면부 골절로 발생한 의료비는 치아관련 치료를
> 제외하고 보상합니다)ㆍ한방치료(다만, 「의료법」 제2조에 따른 한의사를
> 제외한 '의사'의 의료행위에 의해서 발생한 의료비는 보상합니다)…

그래프에 `"에 따라 보상합니다"`로 시작하는 항목은 **0개**였다. 그러니까
조각은 저장된 것이 아니라 **면책검증이 만들어 낸 것**이다.

## 범인

```python
# 조항 앞머리의 상품·조문 이름은 표현 일치에서 빼야 한다 — 아무 청구에나 걸린다.
_PREFIX_RE = re.compile(r"^.*?제\d+조\([^)]*\)\s*")

def _quote(text: str) -> str:
    return _PREFIX_RE.sub("", text).strip()[:QUOTE_CHARS]
```

의도는 `제4조(보상하지 않는 사항)` 같은 **제목**을 떼는 것이었다. 그런데
`^.*?`가 붙어 있어서 **본문 어디에 있는 조문 참조든** 제목으로 오인하고
**그 앞의 모든 글자를 지운다.**

법령문에는 상호참조가 흔하다. `…는 제3조(보장종목별 보상내용) (2)질병급여
제1항 … 에 따라 보상합니다.` 이런 문장을 만나면 면책의 **주어를 지우고
꼬리만 남긴다.**

| | |
|---|---|
| 원문 | 산재보험에서 보상받는 의료비. 다만, 본인부담의료비(…)는 **제3조(보장종목별 보상내용)** (2)질병급여 제1항 및 제3항부터 제8항에 따라 보상합니다. |
| 인용 | `(2)질병급여 제1항 및 제3항부터 제8항에 따라 보상합니다.` |
| | 116자 → 34자 |

더 나쁜 것도 있다.

| 원문 (117자) | 피보험자가 임신, 출산(제왕절개를 포함합니다), 산후기로 입원 또는 통원한 경우(O00∼O99). 다만, … **제3조(…)** … 에 따라 보상합니다. |
|---|---|
| **인용 (11자)** | **`에 따라 보상합니다.`** |

## 얼마나

면책 항목 **1,446개 중 116개(8.0%)**의 인용문이 잘려 나갔다. 최악은 11자다.

가장 중요한 것은 **잘리는 방향**이다. 상호참조는 대개 "다만 …는 보상합니다"
같은 **예외 단서** 안에 있다. 그래서 잘린 인용문은 거의 항상 **면책이 아니라
보상을 말한다.** 판정은 `DENIED`인데 근거는 "보상합니다"다.

이 프로젝트가 내세운 것이 "판정과 **근거 약관 조항**을 함께 낸다"였다.
그 근거가 8% 확률로 정반대를 말하고 있었다.

## 이 정규식은 한 번도 제 일을 한 적이 없다

지우기 전에 확인했다. 면책 조문 68개, 면책 항목 1,446개 전부에 대해
맨 앞이 `제N조(제목)`인 것이 몇 개인지 셌다.

| | 맨 앞이 제목인 것 |
|---|---|
| 면책 조문 68개 | **0개** |
| 면책 항목 1,446개 | **0개** |

조문 파서가 제목을 이미 떼어 `Article.title`로 따로 저장한다(notes/005).
`Article.text`는 `"회사는 다음 중 어느 한 가지로 보험금 지급사유가 발생한
때에는 보험금을 지급하지 않습니다."`로 시작한다.

**떼야 할 앞머리가 애초에 없었다.** 이 정규식이 한 일은 오직 망가뜨리는
것뿐이었다. 그래서 지웠다 — 다듬지 않고 없앴다.

## 표현 일치도 옳은 쪽으로 붙었다

같은 정규식이 `_distinctive_overlap`에서도 쓰였다. 변별어를 찾을 본문에서
앞머리를 떼는 용도였는데, 여기서도 면책의 주어를 지우고 있었다.

금감원 분쟁조정사례 160건 본문 × 면책 항목 440개 = 70,400쌍으로 재 봤다.

| | 불확실 면책 히트 |
|---|---|
| 옛 코드 (`_PREFIX_RE` 적용) | 6,188 |
| 새 코드 (원문 그대로) | **6,413** (+3.6%) |
| 달라진 쌍 | 225 |

늘어난 225쌍이 무엇을 새로 잡는지 봤더니 전부 **면책의 핵심어**였다.

| 항목 | 옛 코드 | 새 코드 |
|---|---|---|
| 치과치료(K00∼K08, …)ㆍ한방치료(…) | `None` | **`치과치료`** |
| 자동차보험(…)에서 보상받는 치료관계비 … | `None` | **`치료관계비`** |
| 사람면역결핍바이러스(HIV) 감염으로 인한 치료비(…) | `None` | **`치료비`** |
| 산재보험에서 보상받는 의료비. 다만, … | `None` | `보상받는` |

옛 코드가 히트를 덜 낸 것은 **더 정확했기 때문이 아니라 문장의 틀린 쪽
절반만 보고 있었기 때문**이다. `치과치료`가 든 면책 항목이 치과 청구에
안 걸렸다.

히트가 늘면 `HUMAN_REVIEW`가 늘어 지급이 줄 수 있다. 그런데 이 방향은
가드레일이 처음부터 택한 방향이다 — 확인 못 한 면책이 남으면 지급하지
않는다(notes/012). 늘어난 것이 **진짜 신호**라면 늘어나야 맞다.

코드 기반 확실 판정(`matches`)은 원문을 그대로 보고 있었으므로 영향이
없다. 데모의 확실 히트 수(2, 3, 0, 0, 0, 1, 0)가 수정 전후 그대로였다.

## 테스트

인용문을 두 가지로 잠갔다.

- `test_quote_keeps_the_subject_of_the_exclusion` — 상호참조가 붙은 실제
  항목의 인용문이 `산재보험에서 보상받는 의료비`로 시작하고,
  `(2)질병급여`나 `에 따라`로 시작하지 않는다
- `test_quote_is_not_a_fragment` — 인용문이 조사로 시작하지 않는다.
  조사로 시작하는 문장은 조각이고, 조각은 근거로 쓸 수 없다

203 passed.

## 배운 것

018·019에서 "표에서 숫자 하나를 찾은 순간이 가장 위험하다"고 썼다. 이번은
결이 다르다. **정규식이 무엇을 지우는지 확인하지 않았다.**

`^.*?`는 "앞쪽 아무거나"라는 뜻이고, 법령문에서 "앞쪽 아무거나"는 대개
**중요한 것**이다. 지우는 코드를 쓸 때는 지운 결과를 세어 봐야 한다. 세어
보니 8%가 망가져 있었고, 심지어 **지울 대상 자체가 0개**였다.

그리고 이걸 여섯 노트 동안 못 봤다. 면책 recall(notes/008)도, 지연
측정(notes/011)도, 오발동 측정(notes/013)도 **히트 여부만 셌고 인용문을
읽지 않았다.** 판정이 맞으면 넘어갔다. 데모 출력에 `"에 따라 보상합니다)"`가
계속 찍혀 있었는데도 지나쳤다.

측정은 결론만 보지 말고 **사용자에게 나가는 문장을 봐야 한다.** 그게 산출물이다.

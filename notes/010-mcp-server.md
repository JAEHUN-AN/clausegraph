# 010 — MCP 서버

약관 지식그래프와 지급심사를 LLM 도구로 노출한다. 공고의 "AI 에이전트와
핵심 업무 시스템 연동"에 대응한다.

붙이는 방법은 [docs/mcp-setup.md](../docs/mcp-setup.md).

## 도구 7개

| 도구 | 언제 부르는가 |
|---|---|
| `list_products` | 어떤 상품·어느 시점을 다룰 수 있는지 모를 때 가장 먼저 |
| `resolve_terms_version` | 조항을 인용하기 전에. 가입일 → 적용 약관 |
| `list_exclusions` | "이거 보상되나요"류. 면책을 **전부** 열거 |
| `check_diagnosis_codes` | 진단코드를 알 때. 코드 범위 대조로 결정론 판정 |
| `screen_exclusions` | 판정까지 가지 않고 면책만 볼 때. 확실/불확실 구분 |
| `search_clauses` | 조항 내용을 묻는 서술형 질문 |
| `adjudicate_claim` | 청구가 자연어로 들어왔을 때. 전체 심사 |

## 도구 설명에 "언제"를 쓴다

kograph에서 배운 것을 그대로 가져왔다. 설명에 "무엇을 하는지"만 쓰면 모델이
도구를 안 고른다. 호출 조건을 적어야 실제로 부른다.

여기서는 한 걸음 더 나갔다 — **부르지 말아야 할 때도 적었다.**

> `search_clauses`: 면책 여부를 가리는 데는 쓰지 말 것. 측정해 보니 이
> 방식은 지급을 뒤집는 면책을 절반 놓친다(recall 32.4%, notes/008).
> 면책은 list_exclusions로 열거해야 한다.

측정치를 도구 설명에 넣은 이유가 있다. 벡터 검색은 그럴듯한 답을 내놓기
때문에, 근거 없이 "쓰지 마라"고만 하면 모델이 무시할 여지가 있다.

## 서버가 되묻게 만든다

instructions에 이렇게 적었다.

> 가입일을 모르면 먼저 물어야 한다 — 같은 조문 번호가 시점에 따라 다른
> 내용이다.

이게 가드레일의 MCP 층 대응물이다. 조항을 인용하려면 버전이 먼저 정해져야
하는데, 클라이언트가 가입일 없이 물으면 시스템이 알 수 없다. 그래서 도구가
답을 만들어 내지 않고 모델이 사용자에게 되묻도록 유도한다.

## 범위 밖이면 거절한다

```
resolve_terms_version("2020-03-01")
-> 가입일 2020-03-01에 적용되던 약관을 수집 범위에서 찾지 못했다.
   list_products로 수집 범위를 확인하고, 범위 밖이면 판정할 수 없음을
   알려야 한다.
```

수집한 약관이 2025-04 이후 4개 버전뿐이라 그 전 가입자는 판정할 수 없다.
**모르는 것을 답으로 만들지 않고, 모델에게 무엇을 해야 하는지 알려 준다.**

날짜 형식이 틀리면 추측하지 않는다.

```
resolve_terms_version("작년")  -> 가입일 형식이 올바르지 않다: '작년' (YYYY-MM-DD)
```

## 모든 결과에 근거 uid를 붙인다

```
check_diagnosis_codes("실손의료보험 특별약관1(중증 비급여 실손의료비)",
                      "2026-07-01", "F32, K08")

-> 걸리는 면책 5건:
   K08 -> 제4조 [(2)질병비급여] 치과치료(K00∼K08) 및 한방치료(…)
     근거 20260506/실손의료보험 특별약관1(중증 비급여 실손의료비)/제4조#(2)질병비급여#3-1
```

uid에 시행일자·상품·조문·보장종목·항호가 다 들어 있어, 모델이 인용한 근거를
사람이 되짚을 수 있다. 지급심사에서 출처 없는 답은 쓸 수 없다.

## 판정은 보조라고 명시한다

`adjudicate_claim` 결과 끝에 "이 판정은 보조이며 최종 결정은 심사자가 한다"를
붙이고, 도구 설명에도 `HUMAN_REVIEW`·`NEEDS_DOCS`가 나오면 단정하지 말라고
적었다. 가드레일이 판정을 강등해도 모델이 "부지급입니다"로 요약해 버리면
강등이 무의미해진다.

## 알아 둘 것

**stdio 서버는 핫 리로드가 안 된다.** 코드를 고쳐도 그 프로세스가 살아 있는
한 옛 코드로 답한다. 수정 후에는 새 대화창을 열어야 한다(kograph에서 겪은
것과 같다).

`search_clauses`는 임베딩 모델을 지연 로딩한다. ONNX INT8 세션을 띄우는 데
몇 초 걸려서, 서버 시작 때 올리면 클라이언트가 연결에서 기다리게 된다.

## 남은 것

- HTTP 전송으로 `/healthz`·`/metrics` 노출 (관측 지표는 W4)
- 도구 선택 정확도 측정 — 어떤 질문에 어떤 도구를 부르는지
- 상품명을 정확히 못 맞히는 경우가 있다. 지금은 빈 결과를 주고
  `list_products`로 확인하라고 안내하는데, 유사 상품명 제안이 필요하다

# 043 — 해외 의료비 지급액과 구조화 입력

## 무엇이 막혀 있었나

해외 병원 영수증으로 시나리오를 만들어 돌려 보니(2026-10-20, 13건) **어떤 입력도
지급액이 나오지 않았다.** 두 겹으로 막혀 있었다.

1. **금액 추출** — `extract.py`의 금액 정규식은 `원` 단위만 읽는다. "USD 1,800"은
   청구액 0원이고, 금액산정은 "청구액이 없어 계산할 수 없다"로 끝난다.
2. **파라미터 부재** — `amount_rules.RULES`에 해외여행 상품이 하나도 없었다.
   원화를 적어 넣어도 "이 상품·보장종목의 지급 파라미터가 없다" →
   `amount_not_computed` → `HUMAN_REVIEW` 0원.

여기에 세 번째 문제가 겹쳐 있었다. 진단코드를 서술에서 다시 추정하므로
**서술의 낱말이 판정을 흔든다.** '오른쪽 손목'에서 C34(폐암)가, '검사비만'에서
E66(비만, 면책 코드)이 나왔다. 후자는 `HUMAN_REVIEW`가 `DENIED`로 뒤집혔다(2회 재현).

## 약관이 정한 것

기본형 해외여행 실손의료보험 제3조 표, (1)상해의료비·(2)질병의료비의 **해외** 행 ①:

> 해외의료기관에서 의사(…)의 치료를 받은 때에는 **보험가입금액을 한도로
> 피보험자가 실제 부담한 의료비 전액을 보상**합니다.

제5조 ①:

> (1)상해의료비 해외, (2)질병의료비 해외의 경우 각각에 대하여 **계약시 계약자가
> 선택한 금액**

그러니까 해외 행은 **공제 없음, 비율 100%, 입원·통원 구분 없음, 한도는 증권 값**이다.
20250401·20250901·20260506·20260910 네 판본 모두 같은 문장이다.

환율은 약관에 0건이다(`환율`·`매매기준율`·`외화`). 환산은 보험사 지급 실무이고 이
시스템의 몫이 아니다 — 앞단이 원화로 바꿔 넣는다.

## 바꾼 것

| 위치 | 변경 |
|---|---|
| `AmountRule` | `limit_from_policy`(한도가 증권에 있다), `abroad_only`(해외 치료에만) |
| `RULES` | `(1)상해의료비 해외`, `(2)질병의료비 해외` — 100%, 공제 0, 한도=증권 |
| `find_rule(..., abroad=)` | **True일 때만** 해외 규칙을 고른다 |
| `compute(..., sum_insured=)` | 한도 = 가입금액 − 이 계약 기지급액. 가입금액을 모르면 한도를 걸지 않고 **상한**으로 표시 |
| `Claim` | `sum_insured`, `treated_abroad` |
| `extract_claim` | `diagnosis_codes`·`claimed_amount`를 주면 서술에서 추정하지 않는다. 명시 코드가 있으면 `enrich`를 부르지 않는다 |
| `adjudicate_claim` (MCP) | `diagnosis_codes`, `claimed_amount_krw`, `treated_abroad`, `sum_insured` |
| 가드레일 4 | 사유를 "공제를 끝까지 계산하지 못했다"에서 "계산에 필요한 값을 확인하지 못했다"로 |

### 왜 `abroad`를 모르면 해외 규칙을 고르지 않는가

같은 상품에 국내(급여) 행이 있고, 그쪽은 붙임 공제와 180일 90회 제한이 붙는다.
치료 장소를 모르는데 해외로 치면 **국내 치료에 공제 없이 100%를 준다.** 반대로
모를 때 아무 규칙도 고르지 않으면 `amount_not_computed`로 사람에게 간다. 덜 위험한
쪽을 기본값으로 했다.

국내(급여) 행 규칙은 이번에 넣지 않았다. 넣으면 `find_rule`이 '상해'/'질병' 부분
문자열로 고를 때 해외·국내 둘이 걸려 어느 쪽도 못 고른다. 국내 행을 넣으려면
`abroad=False`일 때 국내 규칙만 남기는 분기가 필요하다 — 다음 일이다.

### 왜 가입금액을 모르면 상한인가

한도를 지어내지 않는다. 0으로 두면 전부 깎이고(과소지급), 청구액 그대로 두면
가입금액을 넘는 청구에 그대로 준다(과다지급). 그래서 깎지 않은 금액을 계산하되
`missing=("보험가입금액(증권)",)`로 상한이라고 말하고, 가드레일 4가 사람에게 넘긴다.

기지급액도 같다. 해외 행의 한도는 연간이 아니라 **그 계약의** 가입금액이므로,
빠졌을 때 이름을 "올해 기지급액"이 아니라 "이 계약 기지급액"으로 적는다.

## 실측 (니세코 손목 골절, 2026-07-01 가입, 통원 2,500,000원)

| 입력 | 판정 | 지급액 | 가드레일 |
|---|---|---:|---|
| 코드 S62.0 + 원화 + 해외 + 가입금액 1천만원 + 기지급 0 | **PAID** | 2,500,000 | — |
| 위에서 가입금액만 뺌 | HUMAN_REVIEW | 0 | amount_upper_bound |
| 위에서 해외 여부만 뺌 | HUMAN_REVIEW | 0 | amount_not_computed |
| 서술만(옛 방식, '오른쪽' 포함) | HUMAN_REVIEW | 0 | amount_not_computed — 추출 코드 **C34** |

마지막 줄이 이번 변경의 이유를 그대로 보여 준다. 서술만 넣으면 코드는 C34 하나가
되고 금액은 0원이다. 서류에서 뽑은 값을 그대로 넘기면 둘 다 사라진다.

테스트 492개 통과(새로 11개).

## 검토 반영 (2026-10-20)

검토가 HIGH 2건을 실측으로 재현했다. 둘 다 과다지급 방향이다.

**HIGH-1 — 명시 진단코드가 면책 대조를 건너뛰었다.** 구조화 입력의 코드를
`strip().upper()`만 하고 넘겼다. 대조기(`agents.kcd`)는 점 있는 한 개 코드만
읽으므로 아래가 전부 **PAID 2,500,000원**이었다(정답은 DENIED).

| 입력 | 왜 |
|---|---|
| `"S62.0 F20"`, `"S62.0;F20"`, 전각 쉼표, JSON 배열 문자열 | 쉼표로만 나눠 한 덩어리가 됨 |
| `"F200"`, `"E660"`, `"O039"` | 상병마스터의 점 없는 표기 |
| 명시 `S62.0` + 서술 "기왕 진단 F20" | 명시 코드가 있으면 서술 코드까지 버림 |

고친 것: `parse_codes`가 구분자를 다 받고 점 없는 표기에 점을 넣는다. 코드가
아닌 토큰이 하나라도 있으면 `InvalidDiagnosisCodeError` — MCP는 **판정하지 않고**
되돌려 보낸다. 끄는 것은 `enrich`(추정)뿐이고 서술의 정규식 코드(읽은 값)는
합집합으로 남긴다. 전부 빈 토큰은 "주지 않았다"다.

**HIGH-2 — 재심사가 서류의 코드·금액을 버렸다.** `_revise`가 서술을 새로 받으면
`extract_claim`을 다시 돌리면서 명시 코드와 청구액을 넘기지 않았다. 진단서 코드
`S62.0, F20`으로 DENIED였던 건이 서술 "손목 골절 S62.0 진료비 250만원"으로
**DENIED -> PAID**가 됐다. 청구인이 다시 쓴 문장이 서류를 덮어쓴 것이다.

고친 것: `Claim`에 `stated_codes`·`stated_amount`(서류에서 온 값)를 따로 둔다.
재심사는 서술을 바꿔도 이 값을 넘긴다. 고치려면 `revise_claim`의
`diagnosis_codes`·`claimed_amount_krw`·`sum_insured`·`treated_abroad`로 직접 준다.

**그 밖에**
- 0 이하의 `sum_insured`·`claimed_amount_krw`는 "주지 않았다". 가입금액 0원으로
  한도를 걸면 사람에게 갈 건이 "부분지급 0원"으로 확정됐다.
- 가드레일 4의 사유에 빠진 값의 이름을 넣는다 — 스텝을 안 보여 주는 `follow_up`
  에서도 "보험가입금액(증권)"이 보인다.
- LangGraph 구현(`graph_orchestrator._amount`)도 `abroad`·`sum_insured`를 넘긴다.
  자체 vs LangGraph 판정 일치 195/195 그대로.
- 금액산정 스텝의 `detail["rule"]`이 진단코드로 고른 실제 규칙을 적는다.

국내 규칙 계산이 바뀌지 않았다는 것은 검토가 149,760개 조합으로 main과 비교해
확인했다. 이번 수정 후 테스트 551개(검토 반영 +54).

## 2차 반박 검증 반영 (2026-10-21)

검토 반영 커밋을 세 관점(과다지급 사냥 156건 / main 대비 회귀 2,217문장 / 수식어
오탐 7,752조합)으로 다시 깨 보니 지급 쪽으로 새는 길이 더 있었다. 원칙 하나로 막았다
— **확실하지 않은 코드는 버리지도 확정하지도 않고 불확실 면책으로 사람에게 보낸다.**

| 발견 | 재현(고치기 전) | 지금 |
|---|---|---|
| 재심사에 `diagnosis_codes="[]"`·`","`·`'""'` | 서류의 F20 지워짐, DENIED→PARTIAL | "주지 않음" — 달라진 것 없음 |
| 재심사에 공백 서술 | 서술에서 읽은 F20·입원일수 사라짐 | `strip()` 후 "주지 않음" |
| `N3940`(절박요실금) | 요실금 면책(N39.4) 통과, PARTIAL | `CodeRange.contains`가 세분류 **이하**까지 — DENIED |
| X78(자해)·Y36(전쟁)·Z00(검진)·Z23(예방접종)·Z41(미용) | 조문에 코드가 없어 PARTIAL·PAID | 사유 코드 대조표 → 불확실 면책 → HUMAN_REVIEW |
| 서술 "F20으로"·"F200"·"f20" + 서류 코드 | `\b`가 한글 조사에서 안 서 지급 | 앞뒤 영숫자 경계, `parse_codes`와 같은 정규화 — DENIED |
| 국내 상품 + `treated_abroad=True` | 국내 산식으로 지급 | 규칙을 고르지 않음, 사유에 이유 |
| 해외 상품 + 상해·질병 코드 혼합 | 상해 가입금액 하나로 전액 | 규칙을 고르지 않음(보장종목별 구분 필요) |

**약한 코드(`Claim.weak_codes`).** 두 곳에서 나온다 — 병명 수식어가 아닌 앞말에 붙은
짧은 열쇠(`kcd.index.lookup_weak`), 그리고 서류 코드가 있어 판정 코드로 쓰지 않은
사전 추정. 면책 범위에 들면 불확실 면책이고, 보장종목 판별·규칙 선택에는 쓰지 않는다.

**사유 문구.** 가드레일 2(`amount_not_computed`)도 왜 계산하지 않았는지를 괄호로 남긴다
— "지급액을 계산할 근거가 부족하다(해외의료기관 치료를 국내 상품 산식으로 계산하지 않는다)".

**회귀.** 분쟁 코퍼스 2,217문장에서 main의 확실 코드가 면책 범위인데 HEAD에서 완전히
사라진 경우 0건, HEAD가 새로 만든 확실 코드 0건. 확실 → 약한 코드로 내려간 것 86건
(T20 30, A46 23 등 — 사람 확인으로 감). 사라진 것은 의도한 잡음뿐(L71 주사 41, R89 기관
11, T23 손바닥 2). 규칙 표 7/10·헛짚음 0/4, 실제 분쟁 8/10·오발동 2/3·히트 5.7,
자체 vs LangGraph 195/195. 테스트 602개.

**이 PR에서 고치지 않은 기존 결함(main에도 있음)** — 별도 작업으로 뺐다.
- 3대비급여(도수·체외충격파·주사료·MRI) 항목별 한도: `find_rule`이 항목 규칙 대신
  (1)/(2) 규칙을 골라 항목 한도를 다 쓴 계약에도 지급한다.
- 긴 열쇠의 동음이의: '세계자연유산'(O03), '유산소'(유산), '유착방지제' — 임신·치과 면책이
  확실 면책으로 걸린다(과잉 부지급).

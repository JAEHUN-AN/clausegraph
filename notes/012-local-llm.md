# 012 — 로컬 LLM: 붙였고, 기본 경로에는 넣지 않았다

공고 우대사항 "폐쇄망(인터넷 차단) 환경 구축 경험"에 대응한다. 외부 API를
부르지 않고 llama.cpp를 CPU에서 돌린다.

**결론부터: 붙여서 재 봤고, 기본 경로에는 넣지 않기로 했다.** 측정치가
그렇게 말한다.

## 무엇을 맡기려 했는가

notes/009에서 LLM이 필요한 자리를 하나로 좁혀 뒀다. 면책은 코드로 못박혀
있는데(`치과치료(K00~K08)`) 청구서에는 사람 말이 적힌다.

> "충치가 심해 임플란트를 했습니다"

`임플란트`도 `충치`도 약관에 없는 낱말이라 코드로 옮겨야 걸린다. 그 변환
하나만 맡길 계획이었다.

## 환경

| 항목 | 값 |
|---|---|
| 런타임 | llama.cpp b8672 (winget), CPU 8스레드 |
| 모델 | Qwen3-4B-Q4_K_M, 2.38GB, **Apache-2.0** |
| 포트 | 8090 (8080은 이 워크스페이스의 Spring 앱이 점유) |
| 사고 모드 | `enable_thinking: false` — 코드 몇 개에 수십 초를 쓴다 |

Vulkan 백엔드가 로드되긴 하지만 CPU로 돌렸다. 내장 GPU로 얼마나 빨라지는지는
재지 않았다.

## 측정 — 세 가지 방식

평가는 코드 글자를 맞히는지가 아니라 **약관이 못박은 구간에 들어가는지**로
채점한다. 충치를 K02로 적든 K05로 적든 `K00~K08` 면책은 똑같이 걸린다.

두 종류의 오류를 따로 센다. **놓침**은 지급하면 안 되는 건에 돈이 나가는
것이고, **헛짚음**은 지급해야 하는 건이 부지급되는 것이다. 무게가 달라서
하나의 정확도로 합치지 않는다.

| 방식 | 구간 적중 | 헛짚음 | p50 지연 |
|---|---|---|---|
| 규칙 표 (하드코딩 8개) | 5/10 | 0/4 | **0ms** |
| LLM — 코드 **생성** | **3/10** | 0/4 | 4,537ms |
| LLM — 목록에서 **선택** | **11/12** | **3/3** | 2,308ms |

## 1. 코드 생성은 쓸 수 없다

3/10. 규칙 표보다 나쁘다.

처음에는 프롬프트 탓이었다. 예시로 "충치로 임플란트 -> K02, K08"을 달았더니
모델이 **그 코드를 무관한 입력에 그대로 복사**했다 — 요실금·치핵·고도비만·
시험관 시술이 전부 `K02, K08`로 나왔다. 예시에서 구체적인 코드를 빼니 이건
사라졌다.

그런데 고친 뒤에도 3/10이었고, 틀리는 방식이 더 나빴다.

| 청구 | 모델 출력 | 실제 |
|---|---|---|
| 치핵 수술 | `G00.1` (뇌수막염) | K64 |
| 계단에서 넘어져 발목 골절 | `L84.0` (피부) | S82 |
| 임신 중 입덧 | `G98.9` | O2x |
| 고도비만 | `K00.1`, `G00.1` | E66 |

**형식은 맞고 챕터가 틀린다.** 4B 모델은 KCD를 기억하지 못하면서, 기억하지
못한다고 말하지 않고 그럴듯한 코드를 지어낸다.

이게 가드레일 설계의 구멍을 드러냈다. `coder.py`의 모양 검사는 "KCD 표기냐"만
본다. `G00.1`은 표기가 완벽하므로 **통과한다.** 모양 검사로는 이 오류를
막을 수 없다.

막으려면 실제 KCD 코드표가 있어야 한다 — "존재하는 코드인가"를 물을 수
있어야 통과/탈락을 가릴 수 있다. 통계청 KCD-8이나 심평원 코드표를 수집하는
것이 다음 일이고, 그러면 애초에 LLM이 아니라 **용어집 조회**가 맞는 도구가
된다.

## 2. 선택으로 바꾸면 적중은 뛴다 — 그리고 항상 뭔가를 고른다

기억을 요구하지 않는 형태로 바꿔 봤다. 코드를 생성하는 대신, 열거한 면책
항목 13개를 보여 주고 고르게 했다.

적중이 3/10에서 **11/12**로 뛰었다. 예상대로 작은 모델은 기억보다 선택을
잘한다.

그런데 **부정 케이스 3건을 전부 헛짚었다.**

| 청구 | 고른 항목 |
|---|---|
| 보험료를 더 냈으니 돌려주세요 | 보조기 구입비 |
| 계단에서 넘어져 발목 골절 | 보조기 구입비, 산재 보상 |
| 폐렴으로 4일간 입원 | 간병비·증명서 발급비 |

**모델이 NONE을 말하지 못한다.** 맞힌 건에도 여분을 붙였다(충치 -> 치과치료
*와 보조기*, 성장호르몬 -> 호르몬 투여 *와 보조기와 간병비*).

부지급을 이걸로 내면 사고다. 골절로 입원한 사람이 "보조기 면책"으로 거절된다.

## 3. 지연

규칙 0ms 대 LLM 2.3~4.5초다. 심사 파이프라인 전체가 청구당 0.6ms
(notes/011)이므로, LLM을 넣으면 **약 4,000배 느려진다.**

지연만으로 배제할 일은 아니다 — 사람이 심사하는 업무에 2초는 문제가 아니다.
하지만 정확도가 규칙 표보다 낫지 않은 상태에서 4,000배를 낼 이유가 없다.

## 그래서 어떻게 했는가

**기본 경로에 넣지 않았다.** `agents/cli.py`와 MCP 서버는 여전히 규칙 표를
쓴다. LLM 경로는 모듈로 남겨 두고 필요할 때 꽂는다.

만약 넣는다면 이렇게만 넣어야 한다.

1. **선택 방식으로만** — 생성은 챕터를 틀린다.
2. **결과는 불확실 버킷으로만** — `screen()`의 `certain=False`와 같은 취급.
   가드레일이 이미 "확인 못 한 면책이 남았는데 지급하지 않는다"로 걸어
   HUMAN_REVIEW로 보낸다(notes/009). 헛짚음이 부지급을 만들지는 못한다.
3. **DENIED는 코드 대조만** — `agents/kcd.py`의 결정론 경로가 유일하게
   부지급을 낼 수 있어야 한다.

## 이 실험의 범위

모델 하나(Qwen3-4B Q4_K_M), 양자화 하나, 프롬프트 두 형태, 케이스 15건이다.
더 큰 모델이나 KCD로 파인튜닝한 모델은 다를 수 있다. 다만 **작은 모델이
도메인 코드를 기억할 거라 기대하면 안 된다**는 점은 이 규모에서도 분명하다.

## 붙지 않을 때

`code_claim`이 규칙 표로 내려간다. 폐쇄망에서 서버가 안 떠 있을 때 심사가
멈추면 안 된다. `available()`은 예외를 던지지 않고 False를 준다.

## 재현

띄우는 방법은 [docs/local-llm.md](../docs/local-llm.md).

```
uv run --extra graph python -m clausegraph.llm.evaluate --verbose
```

# 016 — 부칙의 상품 범위: 내가 낸 버그를 고친다

notes/015에서 부칙의 적용일을 버전에 붙였다. **그게 틀렸다.**

## 무엇이 틀렸나

notes/015에서 이 부칙을 근거로 `20260506` 버전의 적용일을 `20260606`으로
잡았다.

> 제2조(적용례) 제1조에도 불구하고 [별표15] 표준약관**(개인실손의료보험은
> 제외한다)** 개정내용은 2026년 6월 6일 이후 체결되는 보험계약부터 적용한다.

굵게 표시한 부분을 읽지 않았다. 이 부칙은 적용일을 미루면서 **개인실손의료
보험을 빼 두었다.** 실손은 시행일(5/6)부터 적용된다.

그래서 적용일을 버전 전체에 걸자, 이 프로젝트의 주 대상인 **실손 가입자에게
틀린 약관을 들이대게 됐다** — notes/015에서 고쳤다고 쓴 바로 그 종류의
오류를 다른 방향으로 다시 낸 것이다.

## 상품 범위는 두 방향으로 적힌다

실제 부칙에서 여섯 건이 상품을 한정한다.

| 공포 | 포함 | 제외 |
|---|---|---|
| 20040625 | 자동차보험 | |
| 20110705 | 보증보험 | |
| 20170322 | 실손의료보험 | |
| 20210701 | | 개인실손의료보험 |
| 20250331 | | 자동차보험 |
| **20260506** | | **개인실손의료보험** |

- **제외** — `표준약관(개인실손의료보험은 제외한다) 개정내용은 …`
- **포함** — `별표15 중 <자동차보험> …`, `별표15 중 보증보험 표준약관(…)`

포함 표현이 두 모양이다. 꺾쇠로 묶인 이름은 그 자체로 분명하므로 뒤에
무엇이 오는지 따지지 않고, `표준약관`이 뒤따르는 형태도 함께 받는다.

## 상품명을 어떻게 맞추나

부칙은 `개인실손의료보험`이라 쓰고 약관은
`기본형 실손의료보험(급여 실손의료비)`라 쓴다. 글자로는 맞지 않는다.

수식어(`기본형`, `개인`, `단체`, `특별약관N`, 괄호, 공백)를 떼어 낸 뒤
한쪽이 다른 쪽에 들어 있으면 같은 상품으로 본다.

```
개인실손의료보험              -> 실손의료보험
기본형 실손의료보험(급여 …)   -> 실손의료보험      일치
실손의료보험 특별약관1(중증 …) -> 실손의료보험      일치
생명보험                     -> 생명보험          불일치
```

## 버전 선택이 상품별로 갈린다

`resolve_version(driver, enrolled_on, product)`로 상품을 함께 받는다.

| 가입일 | 기본형 실손(급여) | 생명보험 | 질병·상해보험 |
|---|---|---|---|
| **2026-05-20** | **20260506** | **20250901** | **20250901** |
| 2026-06-10 | 20260506 | 20260506 | 20260506 |
| 2026-09-20 | 20260910 | 20260910 | 20260910 |
| 2025-10-01 | 20250901 | 20250901 | 20250901 |

같은 날 가입해도 상품에 따라 다른 약관이 적용된다. 5/20 가입자는 실손은
새 약관, 생명·질병상해는 옛 약관이다.

## 두 번째 버그: 공유 노드에 표시를 붙였다

`is_own`(그 버전 자신의 부칙인지)을 **Provision 노드에** 저장했다. 그런데
Provision은 uid가 `부칙/공포일자`라 여러 버전이 같은 노드를 공유한다 —
부칙은 세칙 개정 이력 전체가 딸려 오기 때문이다.

그래서 `부칙/20260506`에 `is_own=true`를 붙이자 그 노드를 참조하는 버전
**둘 다** 그것을 자기 부칙으로 여겼고, 모든 버전이 같은 적용일을 갖게 됐다.

```
부칙/20250331  applies_from=None      연결 버전 4개
부칙/20260506  applies_from=20260606  연결 버전 2개   <-- 둘 다 자기 것으로 봤다
```

`is_own`을 **관계**에 옮겨 고쳤다.

```cypher
MERGE (v)-[link:HAS_PROVISION]->(p)
SET link.is_own = coalesce(row.is_own, false)
```

노드에 붙일 값과 관계에 붙일 값을 가르는 기준은 단순하다 —
**"이 사실이 두 노드의 짝에만 성립하는가."** `is_own`은 그렇다.

# 023 — MCP 도구가 에이전트와 다른 답을 내고 있었다

참조 엣지를 붙이고 나서(notes/022) MCP 도구가 새 기능을 노출하는지 보러
갔다. 예외 조항 렌더링을 손보려던 것인데, 그 전에 더 큰 걸 봤다.

## 같은 청구에 두 답

MCP 도구들은 버전을 이렇게 골랐다.

```python
def _version_of(enrolled_on: date) -> str | None:
    with driver().session() as session:
        record = session.run(_VERSION_AT, on_date=...).single()
    return record["effective_from"] if record else None
```

**상품을 받지 않는다.** 세칙 시행일 구간만 보고 고른다.

그런데 심사 에이전트는 notes/016에서 이걸 이미 고쳤다. 부칙이 약관의
적용일을 따로 정하고, **그 적용일이 상품마다 다르기** 때문이다.

> 2026-05-06 개정의 부칙:
> "[별표15] 표준약관(**개인실손의료보험은 제외한다**) 개정내용은
>  2026년 6월 6일 이후 체결되는 보험계약부터 적용한다"

괄호가 결정적이다. 같은 날 가입해도 실손은 새 약관, 생명·질병상해는 옛
약관이다. 에이전트는 `resolve_version(driver, enrolled_on, product)`로
이걸 반영하는데 **MCP 도구는 그 함수를 지나쳐 갔다.**

## 얼마나 어긋났나

가입일을 2025-04-01부터 2026-12-31까지 주 단위로, 상품 16개와 곱해 1,472쌍을
두 방식으로 풀었다.

| | |
|---|---|
| 비교한 (가입일, 상품) 쌍 | 1,472 |
| **답이 다른 쌍** | **32 (2.2%)** |

어긋나는 구간이 정확히 하나다 — **2026-05-06 ~ 2026-06-06 가입, 실손이 아닌
상품 8개.** 그 한 달 동안 MCP는 새 약관을 한 달 일찍 들이댔다.

```
2026-05-12  생명보험            MCP 20260506  vs  에이전트 20250901
2026-05-12  질병·상해보험        MCP 20260506  vs  에이전트 20250901
2026-05-12  자동차보험           MCP 20260506  vs  에이전트 20250901
...
```

2.2%가 작아 보이지만 **어긋나는 방향이 나쁘다.** 개정 직후 한 달은 분쟁이
가장 많은 구간이고, 하필 그때 틀린다.

그리고 이건 이 프로젝트가 README 첫머리에서 내세운 바로 그 오류다.
에이전트에서 고치고 노출 계층에 그대로 남겨 뒀다.

## 왜 생겼나

같은 일을 하는 코드가 두 군데 있었다. notes/021에서 인용문을 고치며 쓴
문장이 그대로 들어맞는다.

> 같은 일을 하는 코드가 세 군데 있으면 한 군데를 고쳐도 고친 게 아니다.

**노출 계층은 로직을 다시 쓰기 쉬운 자리다.** 도구 하나가 "버전만 있으면
되는데" 하고 짧은 쿼리를 직접 부르면, 그 순간 두 번째 구현이 생긴다.

## 고친 방법

`_version_of`가 상품을 받고 에이전트의 함수를 부른다.

```python
def _version_of(enrolled_on: date, product: str) -> str | None:
    return resolve_version(driver(), enrolled_on, product)
```

그리고 **다시 갈라지지 않게 테스트로 묶었다.**

```python
def test_version_resolution_is_the_one_the_agents_use() -> None:
    source = inspect.getsource(server._version_of)
    assert "resolve_version" in source
    assert server.resolve_version is coverage.resolve_version
```

도구 스키마도 검사한다 — 가입일을 받는 도구는 상품도 받아야 한다.

## 상품을 모를 때는 모른다고 말한다

`resolve_terms_version`만 상품 없이 부를 수 있게 뒀다. 사용자가 상품을
아직 말하지 않은 단계가 있기 때문이다. 대신 답에 조건을 붙인다.

```
가입일 2026-05-20 -> 적용 약관 20260506 ~ 20260910 (조문 458개)
이 답은 세칙 시행일자만 본 것이다. 부칙이 정한 약관 적용일은 상품마다
다르므로, 상품이 정해지면 product를 주고 다시 부를 것.
```

상품을 주면 왜 달라지는지까지 말한다.

```
가입일 2026-05-20 / 생명보험 -> 적용 약관 20250901
주의: 세칙 시행일자로만 보면 20260506이지만, 부칙이 이 상품의 약관
적용일을 따로 정해 20250901이 적용된다.
```

모델이 이 문장을 읽고 사용자에게 그대로 전할 수 있다. **틀린 답을 자신
있게 주는 것보다, 조건이 붙은 답을 주는 편이 낫다.**

## 배운 것

**노출 계층을 로직의 일부로 세지 않았다.** 018~022에서 계산기·파서·인용문을
고치는 동안 MCP 서버는 "그냥 감싸는 것"이라고 여겼다. 감싸는 것이 아니라
**두 번째 구현**이었다.

고칠 때마다 물어야 할 것이 하나 늘었다 — *이 로직을 부르는 곳이 여기
말고 또 있는가?* 인용문은 세 곳(notes/021), 버전 해석은 두 곳이었다.

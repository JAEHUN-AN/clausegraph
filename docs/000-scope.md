# clausegraph — 스코프

보험 약관 지식그래프 위에 다중 에이전트 지급심사 보조를 올린다.
청구 건(진단코드·수술코드·입원일수·사고일·**가입시점**)을 입력하면
`지급 / 부지급 / 추가서류요청` 판정과 **근거 약관 조항**을 함께 낸다.

대상 공고: 보험사 IT개발 - AI에이전트 엔지니어.

## 왜 그래프인가 (벡터 검색으로 구조적으로 불가능한 두 가지)

1. **면책은 부정 조건이다.** 보장 조항은 벡터가 잘 찾지만, 그 보장을
   무효화하는 면책·대기기간·감액기간 조항은 다른 절·다른 문서에 흩어져
   있어 놓친다. 지급 판정에서 면책 누락은 오답이 아니라 사고다.
2. **약관에는 시점 축이 있다.** 보험은 *가입 당시* 약관이 적용된다.
   같은 조항 번호가 2015년 계약과 2023년 계약에서 다른 내용이다.
   `(조항)-[AMENDED_BY]->(개정본)` 없이는 최신 약관을 옛 계약에 적용하는
   오답을 낸다.

이 둘을 recall 숫자로 증명하는 것이 프로젝트의 핵심 논증이다.

## 평가셋 2단 구성

- **Tier A (자동)** — FSS 사례 → 지급/부지급 이진 라벨. 목표 50~80건.
  측정: 판정 일치율.
- **Tier B (수동)** — Tier A 중 30건에 정답 근거 조항 직접 라벨.
  측정: 근거 인용 정확도, **면책 조항 recall (vector / graph / hybrid)**.

## 그래프 스키마 (초안)

```
(상품)-[HAS_RIDER]->(특약)-[COVERS]->(보장항목)-[MAPS_TO]->(KCD|수술코드)
(특약)-[EXCLUDES]->(면책조항)
(조항)-[AMENDED_BY]->(개정본)          # 시행일 속성 — 시점 축
(보장항목)-[REQUIRES]->(구비서류)
(분쟁사례)-[APPLIES]->(조항)            # Tier B 라벨
```

## 멀티 에이전트 (5역할)

공고: "여러 AI 에이전트의 역할 분담 및 협업 구조 설계"

1. 사실추출 — 청구서 → 구조화(진단/수술코드, 입원일수, 사고일, 가입시점)
2. 보장탐색 — 그래프 순회로 해당 특약·보장항목 후보
3. 면책검증 — EXCLUDES 경로 + 대기·감액기간 규칙
4. 금액산정 — **결정론 계산기. LLM 금지**
5. 검증/심판 — 근거 조항 없으면 `지급` 불가, 자동 강등

## 가드레일

공고: "핵심 업무 시스템 연동 및 안전장치(가드레일) 설계"

- **Grounding gate** — 모든 결론에 조항 ID 인용 필수. 없으면 `추가서류요청`으로 강등
- **금액은 코드로** — 환각이 곧 지급액 오류가 되는 지점을 LLM에서 분리
- **PII 마스킹** — `C:\workspace\sam-masker` 재사용
- **Human handoff** — 확신도 임계 미달 시 사람에게
- **폐쇄망** — 외부 API 호출 없이 전 경로 동작

## 관측성

공고: "실행 흐름·비용·지연시간 추적, 로그·평가 자동화"

- 에이전트 스텝별 트레이스 → 스텝 latency / 토큰
- p50/p95 집계, **개선 1건을 수치로** (우대: 응답 지연시간 분석·개선 경험)
- 골드셋 CI 회귀

## 제약 (되돌리지 말 것)

- **Anthropic API 크레딧 추가 없음** — 추론 LLM은 CPU 로컬 서빙
  (llama.cpp OpenAI 호환). GPU 없음(`nvidia-smi` 미검출)이라 vLLM 경험은
  주장하지 않는다. 임베딩은 kograph의 ONNX INT8 경로 재사용.
- 관계·조문 추출은 규칙 파서 우선 — 약관은 고정 조문 체계라 정규식이
  LLM보다 정확하고 결정론적이다 (kograph notes/001과 같은 논증).
